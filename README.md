# Словасьянс

Мобильный пасьянс ассоциаций на чистом HTML/CSS/JavaScript — без React и без сборщика. Игра по-прежнему запускается напрямую через `file://`; PWA, service worker и обновления включаются при запуске через HTTP/HTTPS.

## Структура

- `index.html` — основная разметка.
- `styles/base.css` — игровое поле, карты и базовый UI.
- `styles/meta.css` — hub, прогрессия, коллекции, эффекты и модалки.
- `styles/responsive.css` — мобильный адаптив и геометрия.
- `js/config.js` — игровые определения: главы, достижения, темы, рубашки, недельные задания и награды.
- `js/ui/constants.js` — общие названия вкладок и режимов.
- `js/components/ui.js` — переиспользуемая разметка прогресса, режимов и статистики.
- `js/profile.js` — профиль, миграции и настройки.
- `js/data.js` — загрузка и проверка базы категорий.
- `js/generator.js` — seed-генерация, сложность и solver-check.
- `js/engagement.js` — onboarding, недельные итоги, адаптивная сложность, история дуэлей и встроенная проверка.
- `js/meta/systems.js` — энциклопедия, недельные испытания, рекорды, дуэли и перенос сохранений.
- `js/game/*` — правила, drag, game feel и состояние.
- `js/components/*` — переиспользуемые UI-компоненты, карты, поле и game hub.
- `api/analytics.mjs` — анонимные агрегированные продуктовые события в Redis.
- `manifest.webmanifest`, `sw.js`, `icons/` — PWA/offline/update flow.

## Сетевые дуэли

Система дуэлей использует короткие одноразовые коды из 6 символов и Vercel Function `api/challenges.mjs`.

Для production на Vercel нужно один раз подключить Redis-хранилище (рекомендуется Upstash Redis через Vercel Marketplace). API автоматически читает любую из пар переменных:

- `UPSTASH_REDIS_REST_URL` + `UPSTASH_REDIS_REST_TOKEN`
- `KV_REST_API_URL` + `KV_REST_API_TOKEN`

Логика хранения:

1. Автор создаёт дуэль — сервер сохраняет seed/уровень и выдаёт короткий код + приватный owner token.
2. Автор сразу видит созданный расклад в разделе «Дуэли → Активные» и может сыграть его сам.
3. Друг вводит код и получает тот же seed.
4. После первого завершения другом активный код удаляется и больше не принимается повторно.
5. Результат друга временно хранится отдельно, пока устройство автора его не получит.
6. После получения результата автором серверная запись результата удаляется. Локально у автора остаётся карточка матча и оба результата.

При отправке дуэли приложение генерирует PNG-карточку через Canvas и передаёт её через Web Share API вместе с короткой подписью. URL отдельно в share payload не передаётся.

### Обновление истории дуэлей

- У гостя открытая дуэль теперь сохраняется локально в `receivedChallenges`; после победы он остаётся в разделе «Дуэли», даже когда одноразовый код уже удалён с Redis.
- В карточках результатов обеих сторон показываются: звёзды, количество ходов, подсказок, ошибок и отмен.
- Ошибкой считается реальная попытка положить карту в недопустимое место. Возврат карты на исходную позицию ошибкой не считается.
- Share приглашения отправляет одну PNG-карточку с caption: шестизначный код и короткая ссылка вида `https://<host>/?c=ABC123`. Отдельное поле `url` в Web Share не используется, чтобы мессенджеры не создавали второе сообщение.

### Системные уведомления на Vercel

Redis использует те же Upstash-переменные, что и дуэли. Дополнительно создай VAPID-ключи один раз:

```bash
npx web-push generate-vapid-keys --json
```

Добавь в Vercel Environment Variables:

```text
VAPID_PUBLIC_KEY=...
VAPID_PRIVATE_KEY=...
VAPID_SUBJECT=mailto:your-email@example.com
CRON_SECRET=<длинный случайный секрет>
```

`VAPID_SUBJECT` необязателен, но лучше указать свой `mailto:` или HTTPS URL. `CRON_SECRET` обязателен для `/api/reminders`: без него endpoint намеренно отвечает `503` и не запускает массовую отправку. Endpoint принимает секрет только в заголовке `Authorization: Bearer <CRON_SECRET>`.

После этого сделай redeploy. В `vercel.json` уже добавлен ежедневный cron `/api/reminders` на `16:00 UTC` (19:00 по UTC+3). Он отправляет только незакрытый ежедневный расклад и, по воскресеньям, незавершённое недельное испытание. Ответ друга на дуэль отправляется сервером сразу после завершения партии, если игрок разрешил Push.


## Профиль, картинки и уведомления

- Профиль редактируется из верхней карточки игрока: имя, emoji-аватар, титул, любимая категория и до 3 избранных достижений.
- Визуальные карты — это полноценные игровые ассоциации, а не косметика. Сейчас в игре 25 тематических наборов и 150 категорий картинок.
- В настройках уведомлений можно отдельно управлять ответами на дуэли, ежедневным режимом и недельными напоминаниями, а также отправить тестовое уведомление.

## Энциклопедия: слова и картинки

Вкладка «Энциклопедия» объединяет словесные и визуальные категории и показывает общий счётчик прогресса. Внутри есть вкладки «Слова» и «Картинки», поиск, сортировка и фильтры: все, открытые, незавершённые, освоенные и новые.

В настройках можно выбрать источник карт для обычных раскладов: «Только слова», «Только картинки» или «Все колоды». Для сетевых дуэлей выбранный тип колоды сохраняется на сервере, поэтому оба игрока получают одинаковый расклад.

## Product polish / удержание

- Первый запуск начинается с короткого onboarding: имя, аватар, принцип словесных и визуальных ассоциаций, затем встроенное обучение.
- При первой встрече категория открывается отдельным событием и даёт XP; для картинок есть мастерство после открытия всех карточек категории.
- В профиле показываются любимая категория, ежедневная серия, статистика дуэлей и избранные достижения.
- История дуэлей группируется по сопернику и показывает счёт, средние ходы/ошибки и быстрый реванш.
- Раз в неделю формируется персональный итог: партии, уровни, категории, достижения, XP, дуэли и лучшее комбо.
- Сложность обычной кампании мягко адаптируется по последним партиям; ежедневный режим, сетевые дуэли и финалы глав остаются фиксированными и честно сравнимыми.

## Аналитика

Клиент хранит подробную локальную историю в `worditaire-analytics-v1` и дополнительно отправляет на `/api/analytics` только анонимный `clientId`, имя события и timestamp. Имя игрока, слова расклада и содержимое карточек не отправляются.

Для защищённого просмотра агрегатов добавь в Vercel:

```text
ANALYTICS_ADMIN_TOKEN=<длинный случайный секрет>
```

После redeploy статистику за последние 7 дней можно получить запросом `GET /api/analytics?days=7` с `Authorization: Bearer <token>`. Без `ANALYTICS_ADMIN_TOKEN` чтение статистики отключено, запись событий продолжает работать.

Основные funnel-события: `first_open`, `onboarding_complete`, `tutorial_all_complete`, `funnel_level_1_complete`, `funnel_level_2_complete`, `funnel_level_5_complete`, `retention_d1`, `retention_d7`, а также создание/принятие/завершение duel.

## Аккаунты и облачное сохранение

Игра остаётся offline-first: регистрация не обязательна, а одиночный прогресс сначала сохраняется локально. При входе в аккаунт локальный профиль объединяется с облачной копией.

Серверные endpoints:

- `POST /api/auth` — `register_start`, `register_resend`, `register_verify`, `login`, `logout`, `recover`
- `GET /api/auth` — проверка HttpOnly-сессии
- `GET/POST /api/account` — чтение и объединение облачного профиля

Для аккаунтов используется тот же Upstash Redis / Vercel KV, что и для сетевых функций проекта. Нужны существующие переменные `UPSTASH_REDIS_REST_URL` + `UPSTASH_REDIS_REST_TOKEN` (или совместимые `KV_REST_API_URL` + `KV_REST_API_TOKEN`).

Новые аккаунты создаются только после подтверждения email шестизначным одноразовым кодом. Код живёт 10 минут, хранится в Redis только как `scrypt`-хэш, имеет ограничение числа попыток и повторной отправки. Пароль тоже не хранится в открытом виде: во время ожидания кода в Redis лежит только его `scrypt`-хэш.

Отправка кодов работает через Yandex Cloud Postbox по SMTP. В Vercel должны быть заданы серверные переменные:

- `POSTBOX_SMTP_USER` — идентификатор API-ключа сервисного аккаунта с ролью `postbox.sender` и scope `yc.postbox.send`
- `POSTBOX_SMTP_PASSWORD` — секрет API-ключа
- `POSTBOX_FROM_EMAIL` — подтверждённый отправитель на домене, например `auth@solivoc.ru`

Клиент никогда не получает SMTP-секреты: они читаются только Vercel Function. На отправку кодов дополнительно стоят лимиты по IP, email и общий защитный потолок, чтобы не выжечь квоту Postbox.

Резервные коды также хранятся только как `scrypt`-хэш. Сессия хранится в `HttpOnly; SameSite=Lax` cookie; на production/Vercel cookie дополнительно помечается `Secure`.
